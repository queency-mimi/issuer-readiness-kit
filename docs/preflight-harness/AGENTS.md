# AGENTS: preflight-harness

Read `../../docs/AGENT_GUIDE.md`, `../../docs/GATES.md`, `../../docs/CONVENTIONS.md` first; then this project's README, SPEC, ARCHITECTURE, TASKS, RISKS, PRIOR-ART. Work inside this directory only. Do not commit.

Project rules:

1. **Read-only on mainnet.** Mainnet access is HTTP GET (Horizon, `stellar.toml`) and JSON-RPC `getLatestLedger` / `getLedgerEntries` / `simulateTransaction` with **unsigned** envelopes. Nothing is signed or submitted on mainnet. Testnet writes happen only in PFH-021/022 with `Keypair.random()` keys that are never written, logged or committed (G-SECRETS).
2. **Never call a SEP-8 approval server** (a POST can have side effects). Discovery of a regulated asset is `stellar.toml` reading only.
3. **Do not run downloaded code unprompted.** `.competitors/` is created by the user running `scripts/fetch-competitors.sh`. Until then, treat Stellar-Preflight as text: read, grep, never import or execute. The two npm libraries are normal pinned dev dependencies.
4. **Do not copy library code** (G-LICENCE). Mappings and feeders are written from the libraries' public interfaces; if a ticket needs more, record it in `docs/THIRD_PARTY.md` and `NOTICE` after the licence check (Stellar-Preflight MIT, the others Apache-2.0).
5. **Evidence tags and dates on every SIM fact.** Never upgrade a [S] to [P] without a recorded run (fixture with provenance). If a fact you rely on is [U], there must be a spike ticket.
6. **No DTCC claims.** DTC scenarios reference dtc-kit rows by id and carry the weakest row status; every output carries the profile disclaimer; never write "DTC-compatible" (G-DTCC).
7. **Do not redefine dtc-kit's runner or ScenarioPack.** The exporter mirrors dtc-kit's published schema in `src/export/scenario-pack.ts` and is tested against it; if the schema changes, change that module, not the contract. Do not import dtc-kit source (ADR-0002).
8. **Never contact library authors, SDF or anyone** (G-OUTREACH). Findings that look like bugs become `drafts/*.md` for the user (PFH-036).
9. **Fixtures by script, with provenance.** No hand-edited captured fixtures. Synthetic fixtures are generated by `scripts/make-synthetic-fixtures.ts`, labelled synthetic, and never counted as evidence.
10. **Determinism.** Reports must be byte-identical for the same inputs; strip timestamps from `raw`; inject clocks.
11. **TypeScript rules:** Node 24 type stripping, `erasableSyntaxOnly` (no enums/namespaces/parameter properties), `.ts` import suffixes, SPDX header on every source file.

Commands: `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm lint`, `pnpm check`, `node src/cli.ts --help`, `node src/cli.ts adapters`.
